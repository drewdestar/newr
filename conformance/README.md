# Conformance

The corpus in `conformance/` is the single definition of "correct
behavior" for newr. A target that cannot pass it does not ship.

**Seeded in M1 (6 ok + 6 err programs, with expected verdicts asserted
by `tests/test_conformance.py`). Grown in M2 to 68 ok + 22 err programs
(90 total).** The seed covered the front end only: `newr check`
verdicts. In M2 the same programs run through the Python emitter:
`python3 conformance/run.py` builds every ok program, runs the
emitted Python, and requires exit 0 with `PASS` as the last stdout
line - each ok program self-verifies (the honest equivalent of
Gleam's model, since v1 has no in-language test framework). The err
programs assert their `# expect: <CODE>` diagnostic code via
`newr check`.

## The Gleam model

One program goes to every target; the outputs are compared on stdout
and exit code. The same `.newr` source must produce the same observable
behavior from every emitter - Python, TypeScript, Java, C#, Rust,
Kotlin, and Dart.

## Bot mock round-trip corpus

For the `discord` module, the corpus drives bots with the same inputs
and compares the same outputs: replies, balances, and button flows.
A buy in the shop example must leave the same balance and produce the
same replies no matter which target the bot was emitted to.

## Per-target golden files

Each target has golden files: the exact source an emitter is expected
to produce for a given `.newr` input. Golden files are never
hand-edited. They are regenerated by the compiler, and a change to a
golden file is a change to the emitter - reviewed as such.

## One shared escape-test corpus

One corpus covers escaping everywhere: quotes, braces, backslashes,
newlines, emoji, and RTL text. It runs through every emitter, so a
string that is correct in one target cannot silently break in another.

## rustc-style UI snapshot tests

Diagnostics are tested like rustc's UI tests: the compiler's output
for a bad program - file, line, column, message, hint, and snippet -
is snapshotted and compared. A diagnostic that changes wording or
loses its hint fails the snapshot.

## Baselines

Baselines are blessed only after human review. They are never
auto-blessed: a failing snapshot is investigated, not re-recorded
by the test run itself.
